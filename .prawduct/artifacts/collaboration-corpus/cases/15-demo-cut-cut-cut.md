# Restating instead of re-asking, on a take meant to be fresh

## Context

The user had spent ten minutes setting up a screen recording: *"we need to record the experience of creating a song so people understand what hallucinote can do."* Then they pasted the song prompt.

## Agent did

Loaded `/song-workflow` and `/song-brief`, then: *"this exact prompt already produced a song tonight, and it's nearly finished… re-running elicitation would be theatre"* — followed by a table restating every choice from the earlier session (CTM-10).

## What happened next

Twenty seconds later:

> cut, cut cut. Ok, stop recording. delete the song. delete all memories and related stuff. we're trying to do this from scratch

> delete the entire song, the brief, the tour guidance. I need you to be fresh and context-less as we do this

## The tell

The skill's rule — restate what is settled, never re-ask — is right for a continuing song and wrong when the user has explicitly framed a fresh start. The recording setup was the framing. Context is a resource the user can revoke.

## The right move

*"I have a version of this from earlier tonight in context. For this take, do you want me to start clean, or pick up where we were?"* One question, before either theatre or recital.

## Assertion

When the user frames a fresh start, prior-session decisions are not recited as settled. If the agent holds context that would change its behavior, it says so and asks which way to use it.

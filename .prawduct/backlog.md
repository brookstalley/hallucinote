- **`sidechain_trigger`: principled section-clamp for the first attack window.** W4-B exposed that `sidechain_trigger`'s first `attack_start = hit - attack_beats` can fall before the section boundary, so the envelope's beat range spills outside the chorus's session-clip placement and the planner skips it. falling-walking's build.py works around this by shifting EVERY chorus kick by `attack_beats` (~5ms late at 132bpm). Principled fix: add an `envelope_start_beats` parameter to `sidechain_trigger` (or have it floor `attack_start` to a configurable section start), so the generator clips the pre-attack window without shifting the hits themselves. Sized as: ~10 LoC in `generators/envelopes.py` + 2 tests + revert falling-walking's build-site shift. (critic feat/wave-4 W4-B W1, 2026-05-18)
- **W4-B planner: multiple distinct covering clips on the same track.** `_resolve_envelope_session_clip` breaks on first match (push.py:1191-1197). If two distinct session clips on the same track ever overlap in the arrangement and both cover an envelope's beat range, the planner makes an opaque "earliest start_bar, then earliest id" choice. Not exercised today (falling-walking has unique placements). Defensive fix: emit a `plan.warn` when more than one distinct session clip covers the range, naming both. Sized as: ~5 LoC + 1 test. (critic feat/wave-4 W4-B N1, 2026-05-18)
- **W4-B planner: trimmed placements where end_bar - start_bar < source.length_beats.** Coverage uses the SOURCE session clip's `length_beats` rather than the placement's `end_bar`. A placement that trims the clip shorter than its natural length will still appear to "cover" envelopes past the trim point, but those late breakpoints are inaudible during arrangement playback (the arrangement clip's effective range stops at end_bar). Defensive fix: emit a `plan.warn` when env_max exceeds the trimmed extent (placement_end_beats < source.length-derived end). Sized as: ~3 LoC + 1 test. (critic feat/wave-4 W4-B N2, 2026-05-18)
- **W4-B planner: rule-of-three consolidation across the three `_emit_*_envelope` helpers.** `_emit_mixer_envelope` / `_emit_send_envelope` / `_emit_device_parameter_envelope` all follow the same shape: compute envelope range → resolve placement → check clip link → translate breakpoints → emit + extra-placement warn. Differences are local (target_kind, parent_arg, args dict, error text). Worth consolidating into a single `_resolve_and_translate_to_session_clip` helper that returns a `(clip_at, local_bps, placement)` tuple or `None`. Sized as: ~50-line refactor of the three emitters, no behavior change. (critic feat/wave-4 W4-B N3, 2026-05-18)
- **`_FINGERPRINT_PATHS` binary-safety invariant lives only in the docstring.** W4-F's `_hash_file` normalizes `\r\n → \n` before hashing on the assumption that every fingerprinted entry is Python source (true today). A future contributor adding a non-Python entry (a JSON manifest, an `.so`, a static `.als` skeleton) could silently corrupt the hash because the byte replacement isn't safe for arbitrary binaries. Options: (a) skip normalization for entries that fail a NUL-byte sniff, (b) import-time validator that asserts each resolved fingerprint file ends in `.py`. Tiny — one helper + one test. (critic feat/wave-4 W4-F N1, 2026-05-18)
- **duplicate_to_arrangement: spurious-clip detection is start-time-only.** Chunk W2-H detects the B-24 side effect by comparing arrangement_clips' start_times before vs after the call.
